NatureWalk

小さな自然を育てる箱庭 ／ 現行仕様まとめ

概要画面の流れシミュレーションパラメータ 出来事生き物見た目技術構成検討中既知の課題

1. 概要

森・池・川・海の4つの環境を1つの「箱庭（鉢）」に収め、環境（土壌・水質・気候など）を調整して、動植物を絶滅させずに育てるシミュレーションゲーム。Flutter 製で、Web（Chrome）と Android で動く。

目的24季節（6年）の間、できるだけ多くの種を生き残らせる
種の数76種（植物26・鳥26・魚24）。すべて実在の日本の生き物
エリア森／池／川／海（エリアごとに調整できる項目が異なる）
予算開始時 80。季節ごとに 10 ＋ 生き残った種の数 ÷ 2 増える（76種なら約48）
評価最後に生き残った種の割合：90%以上＝S（楽園）、70%以上＝A、50%以上＝B、それ未満＝C
難易度何もしないと24季節でほぼ全滅。保護区・浄化・pH調整などを続ければ72〜76種が残る（自動プレイで確認済み）

箱庭（全体図）の操作

  • ドラッグ：島を回転
  • エリアをタップ：拡大画面へ
  • 「季節をすすめる」：1季節進める（イベント発生・環境変動・個体数更新）
  • 24季節終了で評価ダイアログ →「もう一度はじめる」

エリア拡大画面の下半分（調整パネル）

  • そのエリアで調整できるパラメータの一覧（−／＋ボタン、現在値のバー）
  • 障害物の撤去（10）、保護区に指定（40）
  • そのエリアの種の一覧（写真・個体数・適合度。絶滅した種は「再導入」）

3. シミュレーションの仕組み

3.1 1季節の処理順

  1. 前の季節に出ていた「予報」の出来事が発生（効果を適用）
  2. 環境の自然変動（汚染の流入・酸性化・富栄養化・流れ・酸素など）
  3. 種ごとに適合度を計算し、個体数を増減
  4. 予算を加算し、次の季節の予報を抽選

3.2 適合度（0〜1）

  • 種ごとに、各パラメータの「適した範囲」を持つ（例：ヤマメは水温4〜20℃・酸素70〜100%・流速35〜85%）。
  • 範囲内なら1。範囲外は、離れるほど下がり、パラメータの幅の20%離れると0。
  • 種の適合度＝0.5 × 平均 ＋ 0.5 × 最小（1つでも大きく外れると厳しい）。複数エリアに住む種は、最も適したエリアで評価。
  • 気温には季節補正（春秋±0／夏＋8／冬−8。水域は半分）。猛暑＋6、寒波−6。
  • 鳥は、同じエリアの動植物（餌）の生存割合に応じて ×(0.5〜1.0)。
  • ブルーギルが30匹以上いる池・川では、在来魚の適合度が ×0.8。

3.3 個体数の更新

適合度変化
0.8以上増える：＋20% ＋1（上限100）
0.5〜0.8変化なし
0.25〜0.5減る：−15%
0.25未満大きく減る：−30%（0になると絶滅）

初期個体数は全種10。絶滅した種は、適合度0.6以上のエリアがあれば、予算を払って再導入できる（費用 30 ＋ 珍しさ×10、個体数5で復活）。

5. 出来事（予報 → 発生）

各季節の終わりに、次の季節の出来事を抽選する（約55%で何か起こる）。画面上部に「予報」として表示され、1季節かけて備えられる。発生するとダイアログで知らせる。条件つきの出来事は、環境の状態を満たすときだけ起こる。

大雨・洪水春・夏—川：流速+30・汚染+12／池：汚染+12・酸素−10／森：水分+15
猛暑夏—その季節だけ気温+6（全エリア）

寒波冬—その季節だけ気温−6

種ごとのデータ

  • assets/data/{plants,birds,fish}.json：和名・英名・学名・生息地（複数可）・解説・見分けるポイント・珍しさ（1〜5）
  • lib/data/species_traits.dart：育つ環境の範囲（pH・水分・栄養・気温・日照・塩分・酸素・流速・汚染）
  • assets/images/creatures/{id}.jpg：写真（Wikimedia Commons。CC BY／CC BY-SA／CC0／パブリックドメインのみ）。作者・ライセンスは assets/data/image_credits.json に記録し、詳細カードに表示

珍しさに応じた「姿の見え方」

環境に合っていても、動物がいつもその場にいるわけではない。3Dの表示では、珍しさに応じてときどきだけ姿を見せる。

珍しさ★1★2★3★4★5
基本の出現率90%70%45%25%12%
  • 個体数が少ないほど出にくい（× (0.6 ＋ 0.4 × 個体数/60)）。約20秒ごとに抽選し直し、出入りは短くフェード。
  • 出ていない動物はタップできない。植物は動かないので常に表示。一覧では全種を確認できる。

7. 見た目（演出）

  • 配色・文字：黒背景＋金色（DEEMO 風）。明朝系フォント（Zen Old Mincho）。
  • 箱庭：斜め上から見下ろす擬似3D（アイソメ）。森=奥・池=右・川=左・海=手前の4タイルを、苔むした石積みの鉢に載せる。森の縁から川・池へ小さな滝（全体図のみ）。
  • 地面・水：苔の房と草の穂／透きとおった水（縁は明るく中央は深い、底の小石、さざ波、きらめき、浮かぶ花びら）。
  • 小物：苔むした岩（障害物と飾り）、倒木、スミレ・プリムラ・ヒナギク・スズランの小さな群れ、葦、サンゴ、貝、ヒトデ、漂う蛍の光。人工物は置かない。
  • 生き物のモデル：写真ではなく、形・色・質感で特徴を描く（species_models.dart）。葉は明・中・暗の房を重ね、鳥は覆羽を段にして風切羽を伸ばし、魚はうろこ・光沢・ひれの筋を描く。サクラ＝ピンクの花の雲、スギ＝円錐、カワセミ＝青い背とオレンジの腹、カクレクマノミ＝黒縁の白い帯、など。
  • 種の写真：一覧のカードと詳細カードで使用（3D表示では使わない）。

起動

  • Chrome：flutter run -d chrome
  • Webサーバー：flutter run -d web-server --web-port 8080（http://localhost:8080）
  • Android 実機：flutter run（USBデバッグを有効に）。APK：flutter build apk --release

種を追加する手順

  1. JSON（plants／birds／fish）に1件追加
  2. species_traits.dart に適正範囲を追加
  3. species_models.dart にモデルを追加（鳥：_birdSpecs＋_birdMarks、魚：_fishSpecs＋_fishPattern、植物：_plant／_plantExtra）
  4. 写真を Wikimedia Commons（CC のみ）から取得して assets/images/creatures/ に置き、image_credits.json に作者・ライセンスを記録
外部サイトからの取得は、Python の urllib が社内の証明書で失敗するため、curl を使う。

9. 検討中（未実装）

計画パラメータの抽象化

  • 数値のスライダー操作をやめ、「石灰を撒く」「水草を刈る」のような1操作1ボタンにする。
  • 「診断」を出す：弱っている種が多い原因を集計し（例：「土が酸性に傾き、3種が弱っています」）、対応するボタンをおすすめ表示する。
  • 数値は「くわしい数値」に畳む。

計画発見と駆除

  • 3Dで姿を見かけた種が「発見済み」になる（未発見は「？？？」）。図鑑もこれに連動させる。
  • 発見済みの種だけ「駆除」ボタンで個体数を減らせる。個体数は内部のパラメータで持つ（いまの population を利用）。

計画外来種と生態系のバランス

  • 外来種（現状はブルーギル・ニジマス。セイタカアワダチソウ、ホテイアオイ、ガビチョウ、カダヤシ、オオクチバスなどを追加予定）を、放置すると増えて在来種を圧迫するようにする。
  • 外来種をこまめに駆除して生態系を保つ。在来種を駆除すると、そのエリアが荒れる（適合度が下がる）ようにシミュレーションする。
  • 評価は在来種の生き残りを中心にし、外来種が残ると減点する。

10. 既知の課題

  • 図鑑画面が旧デザイン（緑系）のままで、箱庭と連動しておらず、全種が「???」のまま。
  • 森は種が多く、3D表示で重なりやすい（拡大すると見やすい）。
  • アユの写真は解像度が低い。スイレン・タンポポの写真は属レベルのもの。
  • 観察カード・クイズの画面部品（observation_overlay、quiz_overlay）は未接続のまま残置。
  • 台風などの発生時に、島の見た目（雨・荒れた波など）が変わる演出はない。
  • ゲームの進行を保存しない。
  • 開発用サーバーは、メモリ不足で自動停止されることがある（他のアプリを閉じて起動すると安定）。
